# Prompt Templates

This directory is the navigation index for **reusable AI prompt templates** used by GitHub Copilot
Chat and other AI tools. The actual prompt files live in `.github/prompts/` where Copilot can
discover them. Provider-agnostic prompt and automation guidance lives in `docs/prompts/`.
Prompts should follow the shared provider-agnostic execution flow and safety rules in
[`../assistant-workflow-contract.md`](../assistant-workflow-contract.md).

### CI-Derived (Manually Refreshed)

These prompt files capture CI failure context but are not currently regenerated by an active
GitHub Actions AI workflow. Refresh them with the local generator when a failure pattern changes,
then review the diff before committing.

| Prompt | Trigger |
|--------|---------|
| `workflow-results-code-quality.prompt.yml` | Code Quality workflow failure |
| `workflow-results-test-matrix.prompt.yml` | Test Matrix workflow failure |

## Using Prompts in Copilot Chat

Reference a prompt file directly in Copilot Chat:

```
@workspace /fix-build-errors
```

Or use them as a starting template and customize for your specific task.

## Prompt Generation

The current maintained generator is
[`../../../build/scripts/docs/generate-prompts.py`](../../../build/scripts/docs/generate-prompts.py).
It can analyze workflow results, classify failures, and generate `.prompt.yml` files with failure
context. The legacy prompt-generation GitHub Actions workflow is archived; see
[`../../../archive/docs/workflows/legacy-github-actions-2026-05-18.md`](../../../archive/docs/workflows/legacy-github-actions-2026-05-18.md)
before reintroducing workflow automation.

Run locally:

```bash
python build/scripts/docs/generate-prompts.py --workflow test-matrix.yml --output .github/prompts/ --summary
```

## Adding New Prompts

1. Create a new `.prompt.yml` file in `.github/prompts/`
2. Follow the YAML format used by existing prompts
3. Add an entry to [`.github/prompts/README.md`](https://github.com/rodoHasArrived/Meridian-main/blob/main/.github/prompts/README.md)
4. Add an entry to this README
5. Update [`../../prompts/README.md`](../../prompts/README.md) when adding or changing
   provider-agnostic prompt documentation
