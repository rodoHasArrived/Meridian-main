# Accounting Report Packs

**Owner:** Accounting / Fund Operations
**Scope:** Local workstation API and artifact contracts
**Status:** Operator v1 audit-pack readiness contract added; schema contract v1 remains readable

---

## Purpose

Accounting report packs publish immutable local artifacts for fund-operations reporting from the shared `FundOperationsWorkspaceReadService` and existing `ReportGenerationService`.

The Operator v1 audit-pack slice supports trial-balance report packs for a `fundProfileId`, with manifest, provenance, JSON/CSV section files, an XLSX workbook when requested, audit-pack readiness metadata, and line-level ledger provenance drilldown. It does not add cloud storage or Postgres migrations.

---

## Local Storage

Packages are stored under the retained compatibility folder:

```text
%LocalAppData%\Meridian\workstation\governance-report-packs\<fund-key>\<report-id>\
```

Each package contains:

- `manifest.json` - immutable `FundReportPackSnapshotDto`, including audit-pack readiness when generated by the Operator v1 service
- `provenance.json` - source lineage and source snapshot hash
- `trial-balance.json` when `Json` is requested
- `trial-balance.csv` when `Csv` is requested
- `asset-class-sections.json` when `Json` is requested
- `asset-class-sections.csv` when `Csv` is requested
- `report-pack.xlsx` when `Xlsx` is requested

The API returns relative artifact paths rooted below `governance-report-packs`; it does not return download URLs. The folder and contract name are retained storage compatibility identifiers, not visible workspace taxonomy.

## Schema Contract

Governed report packs use the frozen local export contract:

| Field | Value |
| --- | --- |
| `contractName` | `governance-report-pack` |
| `schemaVersion` | `1` |
| Minimum readable schema version | `1` |

Generation requests may provide `expectedSchemaVersion`. When supplied, it must match the current schema version (`1`); unsupported versions return `400` from the API or `ArgumentException` from the service layer.

The file repository validates the manifest, provenance payload, and artifact metadata before writing. It also skips incompatible future-version manifests during history/detail reads instead of mixing unknown contracts into DK2 pilot evidence.

Audit-pack readiness is additive on schema version `1`. Older manifests that do not contain `auditPackReadiness` remain readable; callers must treat missing readiness as unknown or incomplete, not as a corrupt manifest.

## Routes

| Method | Route | Behavior |
| --- | --- | --- |
| `POST` | `/api/fund-structure/report-pack-preview` | Existing preview-only route. Unchanged. |
| `POST` | `/api/fund-structure/report-packs` | Generates and persists a report-pack artifact package. |
| `GET` | `/api/fund-structure/report-packs?fundProfileId=<id>&limit=<n>` | Lists newest generated packages for a fund. |
| `GET` | `/api/fund-structure/report-packs/{reportId}` | Returns a persisted manifest by report id, or `404`. |
| `GET` | `/api/fund-structure/report-packs/{reportId}/ledger-provenance` | Returns drilldown for a retained report-pack ledger amount. |

Validation:

- blank `fundProfileId` returns `400`
- blank `auditActor` returns `400`
- empty or unsupported `formats` returns `400`
- unknown `reportId` returns `404`
- empty fund data still generates a package and carries warnings in the manifest

## Generate Request

`FundReportPackGenerateRequestDto`

| Field | Required | Notes |
| --- | --- | --- |
| `fundProfileId` | Yes | Fund workspace scope. |
| `auditActor` | Yes | Operator or service identity requesting the package. |
| `reportKind` | No | Defaults to `TrialBalance`. |
| `formats` | No | Defaults to `[Json, Csv, Xlsx]`. |
| `asOf` | No | Defaults to current UTC time. |
| `currency` | No | Defaults from linked fund accounts, then `USD`. |
| `correlationId` | No | Generated when omitted. |
| `decisionRationale` | No | Optional audit note. |
| `expectedSchemaVersion` | No | Must be `1` when supplied. |

Supported `GovernanceReportArtifactFormatDto` values:

- `Json`
- `Csv`
- `Xlsx`

## Snapshot Contract

`FundReportPackSnapshotDto` is the persisted manifest returned by generation and detail routes.

Important fields:

- `contractName`
- `schemaVersion`
- `reportId`
- `fundProfileId`
- `displayName`
- `reportKind`
- `currency`
- `asOf`
- `generatedAt`
- `auditActor`
- `correlationId`
- `decisionRationale`
- `provenance`
- `artifacts`
- `warnings`
- `auditPackReadiness`

Each `FundReportPackArtifactDto` includes:

- `artifactKind`
- `format`
- `relativePath`
- `sizeBytes`
- `checksumSha256`
- `schemaVersion`

## Audit-Pack Readiness

`FundAuditPackReadinessDto` is the operator-facing completeness and timing model attached to generated report-pack snapshots, history rows, and Operations Continuity accounting-record summaries.

Fields:

| Field | Notes |
| --- | --- |
| `isComplete` | `true` only when every required evidence category is complete. |
| `generatedInSeconds` | Measured elapsed generation time for the report-pack/audit-pack snapshot. |
| `slaTargetSeconds` | Constant target value of `60`. |
| `slaMet` | `true` when `generatedInSeconds <= 60`. |
| `missingEvidenceCategories` | Required category keys that were not complete. |
| `warnings` | Operator-visible report, validation, timing, and missing-evidence warnings. |
| `evidenceCategorySummaries` | One row per required evidence category with status text, counts, evidence ids, required evidence labels, and route hints. |

Evidence category keys:

| Key | Required evidence intent |
| --- | --- |
| `SourceRecords` | Retained source records or source snapshot hash. |
| `NormalizedActivity` | Normalized statement, transaction, position, or run activity used by the report. |
| `ReconciliationCases` | Reconciliation runs, open breaks, related cases, and case state. |
| `LedgerEvidence` | Journal entries, ledger rows, trial-balance lines, or ledger posting evidence. |
| `Approvals` | Review, approval, publication, close sign-off, or checklist-control approvals. |
| `ReportPack` | Generated report-pack id, report usage, manifest, and report-line provenance. |
| `Exports` | Retained JSON, CSV, XLSX, manifest, provenance, or evidence-vault export artifacts. |
| `RestatementLineage` | Prior version, changed-line, source hash, or baseline no-restatement lineage. |

The 60-second target is reported as metadata for operator visibility and testable SLA posture. It is not a hard real-time execution guarantee.

## Provenance

`FundReportPackProvenanceDto` captures:

- schema version
- related run ids
- journal and ledger entry counts
- trial-balance row count
- reconciliation run and open-break counts
- Security Master resolved and missing coverage counts
- source snapshot hash

The source snapshot hash is derived from ordered source inputs and summary counts, not from the generated artifact file bytes.

---

## Ledger Amount Drilldown

`GET /api/fund-structure/report-packs/{reportId}/ledger-provenance` returns `LedgerAmountProvenanceDetailDto` for a retained report-pack amount. The drilldown combines:

- provider and source evidence
- normalized strategy/run or statement activity
- Security Master definition evidence
- reconciliation run and case state
- ledger and journal references
- approvals and publication state
- report usage and report-pack artifacts
- audit-pack readiness category evidence
- restatement lineage when retained

Missing categories are returned as warnings where evidence is absent. Audit-ready posture still requires all required evidence categories to be complete.
