# Conformance — the law, run by a machine

**Normative.** Rule ids `C-01…C-16`. Runner: `tests/conformance.html`. Rule source: `tests/conformance-rules.js`. Scoreboard card: `docs/conformance.card.html` (Documentation group).

## Why this exists

4.1's defect list was excellent work found the only way this repository has ever found anything: a person opened the file. That is not a method, it is an availability. And the list was not a set of accidents — it was a **taxonomy**:

```
duplicate hardcoded DOM id       Combobox
no keyboard model at all         DatePicker
missing aria-setsize/posinset    TreeView
row height pinned in px          Stepper · TreeView
transition:all                   Stepper · MultiSelect
missing type="button"            DatePicker
storage write per pointermove    SplitPane
bare Intl.NumberFormat           ten modules
```

Every line is regex-grade. Meanwhile `_adherence.oxlintrc.json` had been generated by the compiler for releases and **nothing in the repository ran it**, and the documentation counts had drifted again — manifest 292 exports / 120 cards against docs 284 / 118 — because the numbers were typed by hand.

Two gates and one scoreboard, then.

## The static gate — sixteen rules (`C-01…C-16`)

| Rule | Catches | Severity |
| --- | --- | --- |
| **C-01** | A bare `Intl` number formatter or `toLocaleString("xx-XX")` outside `core/format.js` | blocked |
| **C-02** | A calendar date routed through `toISOString()` | blocked |
| **C-03** | A literal DOM `id` in a component | blocked |
| **C-04** | `transition: all` against the four motion verbs | blocked |
| **C-05** | A row/control height pinned in px instead of a density token | review |
| **C-06** | A `<button>` with no explicit `type` | blocked |
| **C-07** | A raw hex color outside a `var(--token, #fallback)` fallback | review |
| **C-08** | A remote `@import` or remote `url()` in the token or component layer | blocked |
| **C-09** | A storage write on `pointermove`/`mousemove`/scroll/resize | blocked |
| **C-10** | A positive `tabIndex` | blocked |
| **C-11** | Synthetic list rows without `aria-posinset`/`aria-setsize` | review |
| **C-12** | A font family that is not IBM Plex, declared outside the tokens | review |
| **C-13** | A template that submits an instruction with no declared fate (`ActionEnvelope`) | review |
| **C-14** | An `!important` with no stated reason. The gate used to forbid the string outright, so the four legitimate cases read the same as the illegitimate ones — and prose saying *no `!important` needed* failed too. A declaration that must beat an inline style or a universal descendant rule carries `/* important: <reason> */`; everything else wins by order | review |
| **C-15** | A second declaration of a canonical domain union. `DecisionFlow` kept its own `FinancialObjectType` alongside `ObjectModel`'s, minus `strategy`, so the seventeenth object existed for the header that displays it and not for the flow that approves it | blocked |
| **C-16** | A `templates/<slug>/*.dc.html` entry that is not classified for primitive eligibility — off the record entirely, undeclared as an entry, a primitive left neither eligible nor exempt, or an exemption citing an undeclared reason code. Adoption is published as *conforming ÷ eligible*, so an unclassified screen is in neither term: shipping one shrinks the denominator and the printed percentage reads as progress no migration earned | blocked |

**What the static gate reads.** Every component module, every global token file, and every `.dc.html` entry **declared in `api/template-eligibility.json`** — 35 entries across 27 templates. The template list is deliberately taken from the eligibility record rather than from `_ds_manifest.json`, which names only one entry per template: eight screens are secondary entries inside a classified slug, and while the harness derived its list from the manifest those eight were read by no rule at all and C-16's *undeclared entry* check could never fire. A file present on disk but absent from the record is caught by `scripts/check_template_eligibility.py`, which can list a directory — the browser gate cannot, so disk truth stays with the tool that has it.

**A rule proves itself before its silence is trusted.** Each carries a `fixtures.bad` (a form the rule must flag — in most cases the exact shipped violation) and a `fixtures.good` (the conformant form, on which it must stay quiet). The harness runs those first and reports each as an assertion; a rule that cannot catch its own fixture is reported as failing, because a rule that never fires proves nothing.

## The dynamic gate — the specimen cards

The cards existed and were *looked at*. Now each is loaded in an iframe and asserted against:

- it mounts and renders content;
- no component threw while the bundle evaluated (`__errors` is empty);
- no duplicate DOM id in the rendered tree;
- every control has an accessible name (text, `aria-label`, `aria-labelledby`, a wrapping/associated `<label>`, or a placeholder);
- every `<button>` has an explicit `type`;
- no positive `tabindex`;
- no element computes `transition-property: all`;
- every dialog is named;
- the first control takes focus and shows a visible focus indicator;
- **a published adoption figure recomputes from its own rows.** Scoped to a card that publishes the classification it renders (`window.__eligibility`): every template classifies every primitive, nothing claims conformance on a cell it is exempt from, the declared totals match the rows, and the percentage *printed on the page* matches the one recomputed from them. C-16 proves every screen is on the record; this proves the record's arithmetic and the number rendered from it are the same number. A hand-typed percentage in a card is exactly the drift that let the 284/118 census outlive two releases.
- **every token a component references actually exists.** A `var(--name, fallback)` whose name is defined nowhere in the closure is silently permanent — the fallback becomes the value and no static scan can tell. C-05's own `fix` string named `--row-dense`, `--row-standard` and `--control-h` for two releases; only one of the four names it advised was real, and the `decision/` components duly pinned their rows and tabs to dead tokens where `DensityToggle` could never reach them. A loaded card has the whole closure, so this is the gate that can ask.

Three cards at a time; a full run takes a few minutes. `?cards=all` runs it on load, `?cards=Operations` runs one group.

## The scoreboard

Counts on the harness and on `docs/conformance.card.html` are read from `_ds_manifest.json` at load — exports, modules, cards, templates, tokens. **The claim on the page is the last run**, kept in `localStorage` under `meridian.conformance.lastRun.v1` and readable from `window.__conformance`. Two assertions compare the *typed* counts in `readme.md` and `docs/METRICS.md` against the manifest, so the drift that produced 284/118 is now a failing test rather than a discovery.

## Running it

```
Serve the repository root over HTTP.
tests/conformance.html            static gate + gate integrity + parity (seconds)
tests/conformance.html?cards=all  everything, including the card assertions (minutes)
window.__conformance              { verdict, counts, rules, blocked, review, violations, suites, cards }
document.title                    PASS / FAIL — for a machine that only reads the title
```

A release may not ship with a **blocked** violation or a failing gate assertion. **Review** findings are decisions: fix, or record why not.

## What this gate does not claim

- **Re-render stability**, screen-reader announcement (NVDA/VoiceOver), rendered contrast, and the responsive matrix stay deferred — `tests/BROWSER_TEST_PLAN.md`.
- The **AST-only half** of `_adherence.oxlintrc.json` (per-component prop allow-lists) needs a real linter. The harness loads the emitted ruleset, runs its regex-grade selectors, and *reports the number it cannot run* rather than implying a pass.
- Coverage is by file, not by branch: a rule that no file triggers is silent, which is why the fixtures exist.

## Adding a rule

1. Add it to `RULES` in `tests/conformance-rules.js` with `why` (the defect it comes from), `fix`, `applies(path)`, `scan(text, path)` and both fixtures.
2. Run `tests/conformance.html` — the new rule appears in the table, its two fixture assertions must pass, and any existing violation appears immediately.
3. Add it to the table above, to `tests/README.md`, and to this release's notes — the rule count is typed in all three, so a `counts` gate assertion compares the spelled count and the `C-01…C-NN` range in each against `RULES.length`. C-16 landed with two of them still saying *fifteen*; that assertion is why it cannot happen quietly again.
4. A rule that reads a file other than the one it is scanning takes `(text, path, files)` — `runStatic` hands every rule the whole file map (C-16 is the first to need it), and its fixture carries its own `files` map plus `badPath`/`goodPath`, because a rule whose subject is *which path is on record* cannot prove itself from one path.

The bar for a new rule: it must name a defect the system has actually shipped, and it must be decidable without an AST. Anything else belongs in `guidelines/` as prose until it is.
