The decision spine

A user should move from a portfolio to a position, from a position to evidence, from evidence to a calculation, from that calculation to an accounting consequence, and from the consequence to a governed decision — without crossing semantic boundaries each workstation invented for itself. Six primitives, four new contracts, one sentence.

Context → object → evidence → consequence → decision

Each stage names the component that owns it. A screen that re-derives a stage locally has left the operating language.

Workspace contextEntity · book · basis · period · scenario · currency. WorkspaceContextProvider · WorkspaceContextBar
Time contextTwelve roles across world, book and evidence clocks — as-of, posting, valuation, evidence time. TimeContextProvider
Active objectType, identifier, version, condition, as-of. Sixteen object types, one identity contract. ObjectHeader
Work planeThe dominant plane — table, figure, reconciliation, journal. Never three equal-weight card grids.
Evidence railCoverage → sources → derivation → authority → lineage → audit. SourceCoverageSummary · CalculationTrace · AuthorityStack
Consequence railFinancial effect → records → controls → approvals → reversibility. PostingImpactPreview · ActionGuardList
Decision flowOrdered, guarded, version-aware progression to a committed action. DecisionFlowProvider · DecisionConsequenceBar
SnapshotObject + version + context + evidence set + policy + guards + actor + timestamp — persisted, not reconstructed from UI logs.
Audit narrativeAtomic events stay authoritative; the episode layer and the causal trace are derived views for comprehension.

Four contracts staged this release

Each replaces a class of locally reinvented logic. Full definitions in DECISION_SEMANTICS.md.

ValueAuthoritySix legitimate versions of one value — source, calculated, override, approved, posted, reported. Names which stage is authoritative here, and why. Never "true".
MaterialityAssessmentQuantitative benchmark plus a qualitative factor checklist, with its own policy id. Never abs(variance) > tolerance.
ActionGuardSatisfied · warning · blocking, each with reason, policy, evidence and a named remediation. Visible before the attempt.
DecisionFlowStep order, requirement graph, URL and reload restoration, and invalidation when the object version moves underneath a completed review.

Eligibility, not blanket adoption

Compliance is measured as eligible templates conforming — never as templates referencing. Full table in TEMPLATE_CONTRACT.md.

Context barRequire where context changes data, meaning or permitted actions — not on a Start screen with no analytical context.
Linked selectionRequire where two or more surfaces answer to the same committed selection.
Continuity frameRequire where remote evidence has a useful last-known-good state. Wrap the plane, not the page.
Analytical figureRequire where a visualization supports interpretation, comparison, evidence or a decision.
DatumRequire where zero, target, prior period, tolerance or parity carries analytical meaning.
CapsuleOnly once move and resize actually work, with a keyboard equivalent. Never as decoration.

"Put Datum in 31 screens" is a worse system, not a better one. Raw reference counts diagnose; they are not targets. A 250th component would add less value than eliminating ten locally invented ways to represent period context, selection, tolerance, evidence or approval.
