# Release notes — 4.2.0

**Date:** 2026-09-01 · **Status:** shipped · beta (`docs/QA_REPORT_4.2.0.md`) · **Theme:** the two things the system could not be told, and the one it could not say

Three release-scale items from `docs/reviews/Large Improvements.html`, in the order that made them safe: the harness first, because the numeric sweep moves every number on every screen and nothing would have noticed if it moved one wrongly.

---

## L-02 · A conformance gate that actually runs

`_adherence.oxlintrc.json` had been generated by the compiler for releases and nothing in the repository ran it. 4.1's defect list was a taxonomy — duplicate hardcoded DOM id, no keyboard model, missing `aria-setsize`, pinned row heights, `transition:all`, a storage write per `pointermove`, a bare `Intl` constructor — and every line of it is regex-grade.

- **`tests/conformance.html`** — the runnable gate. Static rules over every component, token file and template entry; assertions over every specimen card; one scoreboard. `window.__conformance` for machines, `document.title` for a CI that only reads titles, `?cards=all` to include the card gate.
- **`tests/conformance-rules.js`** — sixteen rules (`C-01…C-16`), each carrying **the defect it comes from**, the fix, and two fixtures: the shipped violation it must catch and the conformant form it must stay quiet on. The harness runs those fixtures first and reports each as an assertion, because **a rule that never fires proves nothing**.
- **The sixteenth rule guards the adoption figure.** `C-16` fails the release if any `templates/<slug>/*.dc.html` ships unclassified in `api/template-eligibility.json` — an unclassified screen is in neither term of *conforming ÷ eligible*, so shipping one moves the printed percentage with nothing migrated. It is the first **cross-file** rule (`runStatic` now hands every rule the whole file map, because the defect is the absence of a record *about* the template rather than anything in it), and the matching `eligibility` card assertion recomputes `docs/eligibility.card.html`'s totals **and its printed percentage** from its own rows.
- **Scoped severity.** Rules whose defect class is real everywhere but whose *adoption across the 35 template entries* is a release of its own (C-01 numbers, C-02 dates, C-03 ids, C-06 button types) are **blocking in the component tree and a recorded review finding in templates**. Nothing is quietly downgraded: the template hits are listed with file and line.
- **`docs/conformance.card.html`** — the Documentation-group scoreboard. Counts come from `_ds_manifest.json` at load; the verdict is the **last actual run** (`localStorage: meridian.conformance.lastRun.v1`), and reads "NEVER RUN" until there is one.
- **The counts stop being typed.** Two assertions compare the census in `readme.md` and `docs/METRICS.md` against the manifest. The drift that produced 284 exports / 118 cards against a manifest of 292 / 120 is now a failing test. Both files are regenerated: **303 exports across 190 modules · 123 cards · 27 templates · 665 tokens**.
- **Honest about its edges.** Re-render stability, NVDA/VoiceOver, rendered contrast and the responsive matrix stay deferred (`tests/BROWSER_TEST_PLAN.md`). The AST-only half of the emitted adherence ruleset needs a real linter; the harness loads the ruleset, runs its regex-grade selectors, and *states the number it cannot run* instead of implying a pass.

**What the first run found, and what we did with it.** 80 blocking violations on the first run, most of them real:

| Class | Found | Action |
| --- | --- | --- |
| Bare `Intl` / `toLocaleString("en-US")` | 10 modules + 14 more call sites | swept (L-01 below) |
| Literal DOM id (the `Combobox` class) | 6 — `TieOutPanel` `CommandPalette` `Drawer` `ResolutionDrawer`×2 `VersionConflictNotice` | `React.useId()` |
| `<button>` with no `type` | 15 — incl. `Button` itself, `Pagination`, `Toast`, `NumberInput`, `NavRail` | `type="button"` everywhere; **`Button` now defaults to `type="button"`** |
| `transition: all` | 2 — `JournalEntryForm`, `BulkActionBar` | named properties on the house curve |
| Raw hex, remote imports, positive tabindex, storage-on-pointermove | 0 | clean |
| Missing `aria-posinset`/`setsize` (C-11) | 15 | recorded — 4.3 |
| Templates: numbers, dates, undeclared action fate | 34 · 2 · 6 | recorded — 4.3 adoption |

The template figures above rose when the harness stopped taking its file list from `_ds_manifest.json`, which names one entry per template: eight secondary `.dc.html` screens inside classified slugs had been read by no rule at all. Scanning all 35 declared entries added 17 findings (16 numeric, 1 undeclared action) — a backlog that was always there and merely unmeasured. Nothing became blocking.

Four rules were **wrong on the first run and were fixed rather than tolerated**: C-02 flagged `toISOString().slice(11, 19)` (legitimate time-of-day on an instant) until it was narrowed to the `slice(0, 10)` calendar-date extraction; C-06 could not see a `type=` that sat behind a `>` inside a JSX expression; C-07 and C-12 read hex codes and font names out of *comments*; C-05 did not fire on its own fixture. A gate whose false positives are lived with stops being read.

## L-01 · `core/format.js` — the authority numbers did not have

Ten modules each wrote `new Intl.NumberFormat("en-US", …)` while `money.js` and `Timestamp` took a `locale`. The accounting tier — the tier that formats money for a living — was the tier that hardcoded a locale. And precision had no owner either: 4.1 fixed decimals by hand twice.

- **`components/core/format.js`** — the single numeric authority, exactly as `localDate.js` is the calendar-date authority: money, accounting negatives, quantity, price-to-tick, percent, basis points, compact, signed delta, thin separators, house glyphs. **One memoized `Intl` constructor for the whole system** (a blotter formats 50k cells; constructing a formatter per cell was the measurable cost).
- **`components/core/FormatProvider.jsx`** — `FormatProvider` declares the surface once (locale · currency · negative style · numerals · price/quantity precision) and also sets the process defaults, so module-level formatters follow. `useFormat()` hands a component the formatters already bound to it and is safe with no provider. Nest a provider for the one region that must differ. `Format` puts the authority on the namespace for templates and consumer code.
- **Swept:** `BasisComparisonMatrix` `RollforwardMatrix` `PostingImpactPreview` `ScheduleLadder` `VarianceCell` `TieOutPanel` `CommitmentBar` `MaturityLadder` `CashFlowLadder` `MaterialityAssessment` — plus the fourteen bare `toLocaleString("en-US")` callers the gate found (`TaxLotTable` `Figure` `PnLCalendar` `viz` `ValueAuthority` `DataGrid` `ChangeSetReview` `LogTail` `DepthLadder` `OptionChainTable` `OrderTicket`), and `trading-desk`'s own render-edge formatters.
- **`money.js` keeps the arithmetic** the books prove — rounding policy, cent-exact allocation, FX translation, normal-balance classification — and formats through the authority. It re-exports none of the formatters (the bundle shares one scope, so two owners of a name is a collision); the **`Money` carrier composes both halves, so the consumer API is unchanged**.
- **The gate that makes it hold:** C-01. A bare `Intl` constructor outside `core/format.js` is a governance violation, not a style preference. Law: `guidelines/NUMERIC_AUTHORITY.md` (`N-1…N-8`).

**Three deliberate output changes.** Negatives that Intl rendered with a hyphen now render with U+2212 (`RollforwardMatrix`, the compact ladders, the trading-desk money labels); an unknown ISO currency code takes the house narrow-space prefix rather than Intl's non-breaking space. Everything else is byte-identical under `en-US` — which is what the harness was built first to establish.

## L-03 · An action contract — the fate of an instruction

Twenty-seven screens, zero I/O. The system had a deep vocabulary for the provenance of a figure and none for the fate of an instruction: `ActionGuard` answered *may I*, nothing answered *did it*, and `ADAPTER_SEMANTICS` used the word **unlanded** that no submitting control could say.

- **`components/operations/ActionEnvelope.jsx`** — `ActionEnvelope` · `ActionEnvelopeProvider` · `ActionStateChip` · `InstructionLedger` · `ActionHooks` · `ACTION_STATES`. A mutating control **declares** its endpoint, idempotency key, permission, posture and failure surface before the attempt — an undeclared key or failure surface renders *as a defect* — and then renders the only four fates an instruction can have: **in flight · landed · unlanded · rejected**. There is no "failed": a timeout that reads as failure is how a desk sends the same order twice.
- **Dedupe is structural.** A double-clicked Submit is one instruction, and the provider says it deduped. A retry after `unlanded` reuses the key and increments the attempt: it asks whether the first one landed rather than sending a second.
- **`tests/mock-transport.js` + `tests/action-contract.html`** — the transport that lies convincingly (latency, replay, a 4xx with a reason, a 500 whose write landed and whose answer did not, silence) and 24 assertions over it, including the nightmare case: the retry resolves to the **original** receipt and the venue holds exactly one order. The mock lives in `tests/`, never in the templates — the system ships the contract, not a transport.
- **One screen adopted it.** `trading-desk`'s order path now goes through the contract with the desk's own fixture as transport: a ticket submit becomes an instruction whose key is declared up front, and **only a landed instruction reaches the blotter** (posture: confirmed). A new `transport` tweak — *answers · refuses · loses the answer · silent* — exercises all four fates from the Tweaks panel, and the instruction ledger sits under the desk limits.
- Law: `guidelines/ACTION_SEMANTICS.md` (`A-1…A-9`). Adoption gate: C-13.

## Deferred, and why

- **`ingestion-operations`' job queue** — the second screen L-03 asked for. The contract, the mock and one adopting screen are the deliverable; queue adoption lands with the other four C-13 findings in 4.3.
- **C-11 (15 findings)** — `aria-posinset`/`aria-setsize` on synthetic rows is an accessibility pass, not a formatting one, and belongs with the deferred browser/NVDA plan.
- **Template numeric and date adoption (20 findings)** — recorded per file and line by the gate. Templates need a `LocalDate` carrier on the namespace before C-02's template hits can be swept; that is a 4.3 item.
- **Open question 1 is still open.** Whether a screen ends up bound to a real Meridian API or to a convincing mock is the deployment team's call. The contract is worth writing either way; what a mock cannot tell you is which endpoints exist and what they reject.

## Migration

Nothing removed, one behaviour change to know about: **`Button` now defaults to `type="button"`**. A `Button` that was relying on the implicit `submit` inside a `<form>` needs `type="submit"` — which is the explicit form it should always have had.
