MERIDIAN DESIGN SYSTEMRELEASE 4.0 PLAN · 2026-08-12

Plan · major · breaking · supersedes the staged-additions tier

One way to state a value. One way to show a table.

3.1 shipped an operating layer nothing used, and 3.2–3.3 spent two releases adopting it. The staged consolidation tier — ValueEnvelope, DataGrid, Figure, Registry, ScreenComposition — is now in exactly the same position: contracts written, cards drawn, one screen migrated. Meanwhile the components it was meant to subsume are still public, still documented, and still what every other screen uses.

4.0 does not add a capability. It finishes a migration and then deletes what the migration replaced, so a consumer opening this system finds one sanctioned way to build a table, one way to state a value with its condition and authority, and one way to declare a screen.

What this release deliberately does not do05 / 05

Named so they do not creep in.

N-01No new visual designOut of scope

Every migrated screen must read the same as it does today. A migration that also restyles cannot be reviewed, because no diff distinguishes an intended change from a regression.

The one exception is the ops wall, which is new work and gets its own review.

N-02No token changesOut of scope

662 tokens stay as they are. 4.0 is a component-API major, not a retone; a consumer's overrides survive untouched.

Foundations changes wait for 4.1 so the breakage ledger above stays the complete list.

N-03No accessibility claim upgradeDeferred again

The NVDA and responsive matrix stays deferred, as in 3.5. Migrating 32 screens and running a full a11y validation in the same release means neither is trustworthy.

It becomes the headline of 4.1, against a stack that has stopped moving.

D-01Domain ladders vs. the parametric FigureDeferred to 4.1
What shipped

Figure's source claims it "retires" CashFlowLadder, MaturityLadder, ScheduleLadder, IncomeSchedule and DurationContribution. It did not: alm-review still renders all three of the ones it uses, because each carries a domain contract Figure does not model — a stated bucket definition, two-sided comparison mode, and (as of this release) per-bucket value envelopes.

Decision

Figure stays as the sanctioned primitive for a new ladder, plate, distribution or trace, and its docstring is corrected to claim only that. Consolidating the five domain ladders onto it means moving three contracts into Figure's prop surface — a component-API change, so it belongs in 4.1, not in the last phase of this one.

Acceptance test for 4.1: Figure models bucket definition, comparison mode and per-point envelopes; alm-review renders its three planes through it; the five named ladders are deleted.

Open call before phase 1. E-03 — whether exported vocabularies (CONDITIONS, TIME_ROLES, SEVERITY, STRATEGY_LIFECYCLE) are exempt from the cut bar. My recommendation is yes, and that the bar applies to whole modules only. Answering it decides whether phase 1 deletes 2 modules or 30 symbols.
