I-01Run the accessibility validation instead of deferring it a third timedo now
Evidence

guidelines/ACCESSIBILITY.md claims WCAG 2.2 AA tests/BROWSER_TEST_PLAN.md "prepared, deferred, not claimed" 3.5.0 notes a11y matrix deferred 4.0 plan, N-03 deferred again → "headline of 4.1"

The additive a11y extension across 12 primitives (3.5) was real work. What is missing is the run: no keyboard/ARIA matrix result, no NVDA pass, no responsive sibling check, against 268 exports and 26 screens.

The move

Turn the plan into a harness rather than a report. Assertion-based DOM checks over the 111 existing cards — every interactive card gets roving-focus, name, role and Escape assertions — plus a per-component scoreboard card in the Documentation group, so the claim on the page IS the last run.

Then reduce the prose claim to what the harness covers and name the rest as untested. A system that says "keyboard: untested" is more trustworthy than one that says AA and can't show it.

I-04The whole type system is one request to a Google CDNdo now
Evidence

tokens/fonts.css @import url("https://fonts.googleapis.com/css2? family=IBM+Plex+Sans…&family=IBM+Plex+Mono…") + @font-face { src: local("IBM Plex Sans") } readme "no webfont binaries ship for them" → contradicted by the file above

An air-gapped or egress-filtered install gets system-substituted faces: the mono numerics that "never jump" jump, and the 14px body ramp is set in something else. Nothing in the system reports this.

The move

Self-host the subset — the four weights of each family, Latin, woff2, in assets/fonts/ — with the Google import kept only as an optional CDN variant. Roughly 200 KB, cached forever, and it removes a runtime third-party dependency from an institutional deployment.

Then correct the readme's font paragraph, and add a governance gate: no remote @import in the token closure.

Cost one sitting + a licensing check (Plex is OFL) · Payoff the type actually renders as designed, offline

I-05Icons are 48 files and 60-odd relative paths, not a componentdo now
Evidence

assets/icons/ 48 svg modules 4.0 phase 1 core/icons.js deleted (7 Glyphs) templates/ a dozen files carry literals like icon: "../../assets/icons/dashboard.svg"

Copy a template folder into a consuming project — the documented first step — and every nav icon 404s until the consumer rewrites the paths or copies assets/ by hand. The iconography guideline says 16–20px, currentColor, no icon font; nothing enforces or delivers that.

The move

An Icon primitive over a compiled sprite: <Icon name="dashboard"/>, stroke inherits currentColor, size from the density scope, unknown name renders a visible placeholder rather than nothing. NavRail takes a name; the path form stays as the escape hatch for product-specific art.

This is also the one place where deleting core/icons.js left a hole rather than closing one.

Cost a sitting for the sprite compiler, one for the template sweep · Payoff template copies work unedited
