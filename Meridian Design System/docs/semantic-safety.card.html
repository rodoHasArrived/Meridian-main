Semantic safety, and what it unblocks

One rule, applied to every surface that decides something: a surface may assert only what something established. Absence is a state with a name — never a zero, never a pass, never an elapsed clock standing in for an acknowledgement. Increment A is shipped on this tree; B and C are proposed and stated here so the order is legible. Full record: docs/SEMANTIC_SAFETY_4_4.md.

shipped

Does a surface ever assert something nobody established?

Retires: absence read as agreement — a missing input reading tied, an empty panel reading ready, a timeout dressed as an acknowledgement.

Contract and test work only. Nothing migrated across the 28 templates — deliberately, because the negative paths land first.

ActionEnvelopeProvider With no transport it answered { ok: true } to itself and minted a local receipt id — every instruction “landed” against nothing. Landing requires ok === true from the transport and takes the receipt id from the adapter. No transport, an unreadable answer, and a refusal without a reason are all unlanded. Demos pass a named fixtureTransport(). semantic-safety › transport answers (11) · action-contract
ActionQueue Promoted a row to “Accepted by the adapter” after 1.5 s of wall time. Every rung is read off the answer. landed with an adapter receipt is confirmed; without one it is only acknowledged and stays unresolved; unlanded is timed out, and its ladder never draws an acknowledgement that never happened. semantic-safety › queue rungs (6)
…retry() A retry with nothing to retry fell through to submit(), minting a fresh idempotency key — the one thing the unlanded fate exists to prevent. A no-op that says so; a real retry carries the same key with an incremented attempt. semantic-safety › no instruction, no key
TieOutPanel Coerced a missing source to 0, so the gross difference vanished and the panel read Tied out. A source with no value — or one carrying missing / pending / stale / na / exception — makes the tie-out indeterminate: residual renders as —, each gap is named, acceptance and resolution are unavailable, and a caller-declared status="tied" cannot outrank it. semantic-safety › a missing input is not a zero (6)
AttestationPanel An empty panel derived Ready for attestation — no gates to fail, no evidence to fall short of, nothing bound. Readiness is asserted from what is declared: absent gates, evidence set, snapshot, version or signatory roles are named as under-declaration. A snapshotFindings entry with effect void expires the pending signature; a caller-declared ready survives neither. semantic-safety › readiness is asserted (8)
JournalEntryForm Gated Post on arithmetic alone. blockers — a changed reviewed snapshot, a closed period, a withdrawn approval — are named on the form and disable Post. Balance is a precondition for posting, not permission to post. semantic-safety › arithmetic is not permission (3)
Assurance A re-preparation after a movement dropped every earlier signature on the floor. Signatures append, never replace. assuranceState splits the trailing run that still binds the balance (live) from what a movement voided (history); both are retained, and Assurance.history() reads the whole chain oldest-first. semantic-safety › history survives a re-preparation (6)
assurance.card One click walked an account up the ladder by inventing a preparer, then a reviewer, then a controller. One signed-in operator acting in one authority. An account that needs a different authority — or a second person — refuses, and says which. the card renders the refusal
Increment A — exit checks
  • ✓No missing input yields tied or ready by default — and a caller cannot declare its way past one.
  • ✓No timeout implies acknowledgement: rungs come from the answer, and ackMs is accepted and ignored.
  • ✓No unvalidated transport response becomes confirmed — ok === true plus an adapter receipt id, or it stays unresolved.
  • ✓A re-preparation retains historical signatures: voided, struck through, never deleted.
  • ✓Changing the reviewed snapshot invalidates the pending action — the attestation expires, the post is blocked.
  • ✓Server authority remains the final enforcement boundary: every declaration still reads declared here, enforced by the server.
  • ✓Fixture transports stay explicitly named; an absent transport is a warning plus an unlanded instruction, never a silent success.
  • ✓Negative-path tests land before broad migration — 46 assertions across 8 suites, each suite carrying a positive control so a rule that blocks everything fails too.
