ReturnPath

Meridian's handoffs were one-way. Reconciliation opened accounting and close opened the tie-out, but the returns were never built — a journal entry could not open the break that caused it, and an account sheet could not open its own reconciliation. Operators work in loops, not chains. This renders the loops templates/_scaffold/app-map.js declares for an object type.

A loop appears only when the object carries the link. MeridianAppMap.loops("break", brk) reads the record in hand: an unresolved break offers no “entry that resolved this”, because there isn't one. The affordance is never a dead promise — which is the whole difference between this and a “View related” menu.

Nothing to return to

Renders null by default — an object with no way back shows no control, not an empty row. emptyText only when the absence is worth stating.

<ReturnPath loops={[]} emptyText="No upstream object — posted directly." />
Declared centrally, rendered locally. The relations live in one place (app-map.js › LOOPS): entry ⇄ break, break ⇄ account, task ⇄ tie-out, position → security, run → strategy. Add a relation there and every screen holding that object type gains the return. MeridianAppMap.loopActions(type, obj) gives the same loops as palette rows, so a return is also reachable from Ctrl K.
