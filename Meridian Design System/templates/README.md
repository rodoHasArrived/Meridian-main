# templates/ — 28 copy-and-edit screens

Two kinds live here, same anatomy, same contract.

**8 archetypes** — one reference screen per picker group, the reference **composition** for its kind of screen: **Start** (`blank-workstation`, `session-start`) · **Monitor** (`dashboard-workstation`) · **Investigate** (`analytical-workbench` for the figure grammar, `interaction-depth` for the interaction cluster — 50k-row grid, right-click verbs, bulk edit, saved views, keyboard-only path, optimistic edits that revert with a reason, annotations versioned with the object, comparison by selection) · **Compose** (`basket-builder`) · **Report** (`report-pack`) · **Admin** (`settings-admin`).

**20 production screens** — Meridian's own surfaces (accounting, trading desk, reconciliation, security master, ingestion ops, ownership graph, the four-template / seven-screen Strategy suite on one shared store…). They are *consumers* of this system, reaching it only through the compiled bundle + `styles.css`; upstream they sat in a separate `meridian-screens/` tier staged for extraction, and in this project they sit here because this is the tree the picker indexes. Several are **multi-view survivors of the 4.0 merges** — `reconciliation` (queue → matcher → exception), `close-management` (close plane + tie-out drill-in), `strategy-runs` (ledger + backtest + compare + lab), `accounting-workstation` (books + journal compose mode) — each retired surface reachable as a `view` tweak or URL param. Three walk end-to-end **composition chains** with real state — `reconciliation`, `close-management`, `alm-review` — so the handoff between components (a variance opening a tie-out, a break becoming an exception, a resolved blocker releasing an attestation gate) is demonstrated rather than described. Copy one when the screen you are building is a *sequence of consequential decisions*, not a single view. Surface → template + variant map: `PRODUCTION_SCREENS.md`.

**Which do I copy?** Building a screen Meridian already has → the closest production screen. Building a new *kind* of screen → the archetype for its group.

**Anatomy** (`<slug>/`):

- `PascalCase(<slug>).dc.html` — the entry, and where the screen's **content** lives as directly editable markup: headings, panel titles, KPI labels, table column labels, copy. First line inside the markup: `<!-- @template name="<Group> · <Name>" description="…" -->`.
- `ds-base.js` — **generated.** Loads `styles.css` (which `@import`s the whole token closure — dark mode, contrast modes, print) plus `_ds_bundle.js`, and owns the chrome the *system* owns rather than any one screen: the contract's Live/Paper/Fixture badge, and (4.4) the **live masthead search field** — it mounts `GlobalSearch` and binds both the topbar button and `/` to it, so the field is real on every screen with no per-screen wiring. It also loads the two spine files below. Adjust the one `base` line if the copy sits at a different depth; never edit anything else here. Canonical source: `_scaffold/ds-base.js`.
- `../_scaffold/app-map.js` + `../_scaffold/world.js` + `../_scaffold/prefs.js` — **the suite spine, loaded by `ds-base.js`, referenced in place** (4.4 · `../docs/SUITE_COHESION_4_4.md`). `app-map.js` is the one address book: every rail section, every route, every `G` chord, `open(type, id)` for the 21 object types, and `LOOPS` — the declared **return** for each of them, so a journal entry can open the break that caused it (`MeridianAppMap.loops(type, obj)` → `ReturnPath`; `loopActions()` for the palette). A screen's whole nav is `sections: MeridianAppMap.sections("<id>")` + `onSelect: MeridianAppMap.go`. `world.js` is the one shared fiction: a **ticking** `NOW` (so the wall clock and the "live" pulse dot stop contradicting each other), one business date and close period, one signed-in `OPERATOR`, canonical `ENTITIES`, and feed health derived from the clock. `prefs.js` makes theme, density and environment **survive a navigation** — tweak seeds, operator wins.
- `../_scaffold/operator-layer.js`, `trail-bridge.jsx`, `action-bridge.jsx` — **shared, referenced in place** (not copied per folder). Copy `_scaffold/` along with any archetype. `operator-layer.js` also publishes the screen's live layer as `MeridianOperatorLayer.current`, which is how `ds-base.js`'s search field reaches the current screen's own objects.
- `screen.jsx` / `views/` (optional) — only what needs React: interactive tables, charts, dialogs, live state. Mounted via `<x-import>`. Compose the frame with `WorkstationShell` where you can; it owns the chrome and renders the `<main>` landmark.
- `<slug>-data.js` (optional) — large seed-data literals. Load as a plain `<script>` in the `.dc.html` **static `<head>`, before `support.js`**, so the data exists before `screen.jsx` reads it at module level. Never from `<helmet>` or a second `<x-import>` — neither guarantees execution order.
- `support.js` — **generated** DC runtime; never edit.

**Tweaks.** Every entry declares the same four in `data-props`, on top of anything screen-specific: `density` (`default`/`compact`/`terminal`/`spacious`), `theme` (`light`/`dark`), `environment` (`PAPER`/`LIVE`/`FIXTURE`), `dataState` (`ready`/`loading`/`empty`/`error`). The first three map onto the design system's own token scopes (`<html data-theme>`, `<body data-theme-density>`, `<html data-environment>`) **through `MeridianPrefs`** — the tweak seeds a first visit, an operator choice in the masthead menu wins and persists across screens; the fourth drives the `DataStateSwitch` wrapper around the dominant work plane, so a copied template ships loading, empty and error — not the happy path alone. `$preview` sets the picker's thumbnail size.

**Operator layer** (4.2 · every archetype, production screens next). Each archetype loads `../_scaffold/operator-layer.js` after `ds-base.js` and mounts three things outside the work plane: `CommandPalette` (`Ctrl K` — commands + **object lookup** via `resolve`, verbs on a row, session recency), `HotkeysProvider` (`?` sheet generated from the same bindings), `ToastProvider`. The logic class declares one `operatorLayer()` returning `MeridianOperatorLayer.build({ sections, activeId, go, actions, objects, verbs })` — NavRail `shortcut`s become `G x` chords automatically; `actions` are `{id,label,keys?,run,danger?}`; `objects` are `{type,id,label,keywords?,open}` and make the palette answer "find X". Screens with objects also wrap the plane in `ObjectTrailProvider` (`storage=sessionStorage` — session-only by decision) with `ObjectTrail` in the context region and `trail-bridge.jsx` handing the API to the class; multi-region screens use `WorkspaceLayout` the same way. Screens that **write** wrap in `ActionEnvelopeProvider` + `action-bridge.jsx` and mount **`ActionQueue`** in the corner, so a commit / save / deliver stays visible as submitted → acknowledged → confirmed | rejected | timed out. Reference: `dashboard-workstation` (palette + trail), `basket-builder` (all three incl. queue), `blank-workstation` (minimum).

**Consume:** copy the folder → open the `.dc.html` → edit the markup → fix `ds-base.js`'s one `base` line if needed. Start with `dashboard-workstation/` (the reference screen, and the reference split between editable markup and React) or `blank-workstation/` (bare shell). Full index with one-liners: `../readme.md`.

**Contract** (upstream, enforced by `scripts/check_design_system_governance.py`; in this project the design-system compiler checks the structural half): PascalCase entry name · viewport meta · `<main>` landmark · `<h1>` · visible Live/Paper/Fixture badge · `$preview` · the four standard tweaks · a `DataStateSwitch` around the work plane · scaffold in sync with `_scaffold/` · components reached only through the compiled bundle. `WorkstationShell` is recommended, not required — hand-rolled chrome must still satisfy the contract.

**Cohesion rules** (4.4, `scripts/check_suite_cohesion.py` — **advisory**; `--strict` makes it a gate). The contract above asks "is this screen well-formed?"; these ask "do the screens add up to one workstation?" — a suite can pass every structural gate and still be 27 dioramas. `env` every environment is LIVE/PAPER/FIXTURE and never a literal contradicting the screen's own tweak · `nav` no rail renders with a no-op `onSelect`, and a rail-less screen must be a declared exemption (pre-auth, wallboard, specimen, print artifact) · `map` rails and routes come from `app-map.js`, not a hand-rolled table · `label` the masthead name matches the screen's app-map label, so the rail entry that links to it and the masthead you land on agree · `clock` no screen hardcodes a wall clock · `prefs` chrome attributes go through `MeridianPrefs`, so an operator's display choice is not overwritten on every render · `operator` the masthead identity is suppressible only pre-auth · `search` `ds-base.js` is present · `world` no screen retypes the fund name or business date.

**Generated scaffolding:** upstream, `python scripts/sync_template_scaffold.py` rewrites every folder's `ds-base.js` and `support.js` from `_scaffold/` (`--check` fails on drift). That tooling is not ported here — if you touch `_scaffold/`, mirror the change into each folder by hand and never hand-edit a per-folder copy otherwise.
